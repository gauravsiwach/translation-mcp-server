# Implementation Plan V2: Migrate to pepsi_translations / pepsi_languages

## Overview

The existing system uses its own demo tables (markets, translations, market_locales, etc.).
We remap everything to **2 pre-existing production tables** in the `customer_uat_ind` schema,
keep only minimal CRUD + AI-translate features, and strip all demo-only concepts.

---

## Target DB Schema (pre-existing, no migrations needed)

```sql
-- Schema: customer_uat_ind

pepsi_languages (
    language_code  VARCHAR(10)  PRIMARY KEY,
    language       VARCHAR(100) NOT NULL,
    created_datetime TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP,
    updated_datetime TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP
)

pepsi_translations (
    id              BIGINT       PRIMARY KEY  GENERATED BY DEFAULT AS IDENTITY,
    label           TEXT         NOT NULL,
    language_code   VARCHAR(10)  NOT NULL     REFERENCES pepsi_languages(language_code),
    translation     TEXT         NOT NULL,
    type            VARCHAR(255),
    created_datetime TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP,
    updated_datetime TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP
)
```

---

## Decisions

| # | Decision |
|---|----------|
| 1 | No Alembic migrations — tables already exist, we do not own the schema |
| 2 | No versioning / audit trail — not in new schema |
| 3 | No market concept — `language_code` is the sole locale identifier |
| 4 | AI translate = **upsert** (update if label+language_code exists, insert if new) |
| 5 | `label + language_code` uniqueness enforced at **service level** |
| 6 | `type` field = free text, no restriction |
| 7 | API = open, no auth for now |
| 8 | MCP server = already running **SSE/HTTP on port 8001** (no change needed) |

## Phase 6 — Bulk Operations & Batch Processing (Enhancement)

### Overview
Add bulk create and batch processing capabilities to support:
- **Tool mode**: MCP client translates locally, saves multiple translations at once
- **Large-scale AI translations**: Process 10+ labels with auto sync/async

---

### Step 6a — Modify `create_translation()` for Bulk Support
**File:** `src/services/translation_service.py`

**Change signature:**
```python
async def create_translation(
    session,
    translations: Union[Dict, List[Dict]],  # Accept single OR array
) -> Dict:
```

**Logic:**
- Detect if input is single dict or array
- **Single dict:** Keep current behavior (check duplicate, insert, commit)
- **Array:** Loop through each item:
  - Check if `label + language_code` exists
  - If exists: Update `translation` and `type` fields
  - If new: Insert new row
  - Track created vs updated count
- **Return format:**
  ```python
  # Single
  {"id": 1, "label": "...", "language_code": "...", ...}
  
  # Array
  {"total": 10, "created": 7, "updated": 3, "results": [...]}
  ```
- **Transaction:** Single commit at the end for array operations

---

### Step 6b — Modify `ai_translate()` for Batch Processing
**File:** `src/services/translation_service.py`

**Change signature:**
```python
async def ai_translate(
    session,
    translations: Union[Dict, List[Dict]],  # Accept single OR array
) -> Dict:
```

**Logic:**
- Detect if input is single dict or array
- **Single dict:** Keep current behavior (call AI, upsert results)
- **Array:**
  - Check array length
  - **≤10 items:** Sync mode
    - Split into batches of 10 (if needed)
    - Call AI for each batch
    - Upsert results to DB
    - Return full results
  - **>10 items:** Async mode
    - Generate unique `batch_id` (UUID)
    - Store initial status in `batch_status` dict
    - Start background task to process batches
    - Return `batch_id` immediately
- **Batch processing logic:**
  - Split array into chunks of 10
  - For each chunk: Call `ai.agent.generate_translation()`
  - Upsert results (update if label+language_code exists, create if new)
  - Update `batch_status` dict with progress
- **Return format:**
  ```python
  # Single or ≤10 items (sync)
  {"mode": "sync", "label": "...", "upserted": [...], "total": 5}
  
  # >10 items (async)
  {"mode": "async", "batch_id": "abc123", "total_requested": 50, "status": "processing"}
  ```

## Phase 6 Summary: New vs Old Features

### New Features Added
1. **list_languages** - New MCP tool to fetch available locales from pepsi_languages table
2. **Unified ai_translate** - Single tool handles both single and bulk, auto sync/async detection
3. **Upsert logic** - create_translation automatically creates or updates based on label+language_code
4. **Auto sync/async detection** - ≤10 items sync mode, >10 items async mode (no user choice needed)
5. **Efficient AI batching** - 1 AI call per 10 items instead of 1 AI call per item
6. **In-memory batch status** - Track async operations without database overhead
7. **Batch status endpoint** - `GET /translations/batch/{batch_id}/status` for async progress tracking
8. **Mode-specific tool enforcement** - Windsurf rules enforce correct tool usage per mode

### Features Removed (From Old System)
1. **approve_translation** - Approval workflow removed
2. **reject_translation** - Rejection workflow removed
3. **prepare_translations** - Two-step prepare → save flow removed
4. **save_translations** - Replaced by create_translation with upsert logic
5. **add_translation** - Replaced by ai_translate (handles single item)
6. **add_translations_bulk_sync** - Replaced by ai_translate (auto-sync for ≤10)
7. **add_translations_bulk_async** - Replaced by ai_translate (auto-async for >10)
8. **Market selection** - Fixed to India (PEPSI) only, no multi-market support
9. **Environment selection** - Simplified, no longer needed
10. **Propagate markets** - Removed (India-only system)
11. **Screen ID parameter** - Removed from translation schema
12. **Batch size 50** - Reduced to 10 for sync mode (better performance)

### Windsurf Rules Changes
- **Two modes retained**: API mode (ai_translate) and Tool mode (create_translation)
- **India-only**: Market fixed to PEPSI India, no market selection
- **Locale selection**: Uses list_languages to fetch available locales
- **Existing key check**: Asks "update or skip?" for existing keys
- **Natural language parsing**: Simplified, no market inference needed
- **Strict tool enforcement**: API mode can't call create_translation, Tool mode can't call ai_translate
